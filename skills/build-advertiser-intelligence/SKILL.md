# Build Advertiser Intelligence

Establish the advertiser, official website, business question, requested markets and output scope. Reuse existing project evidence before buying more collection. A business-only request needs only business research.

## Choose execution from the request

For inline research, use the currently discovered search, website, social and paid-ad tools to answer the business, customer, competitor and creative questions relevant to the brief. `creative_os_load_local_specialist` can supply existing domain guidance; it does not enable a disabled hosted skill or start a cloud job. Execute through available tools and return findings directly; inline work does not require worker submission tokens.

For requested cloud work, use `creative_os_publish_specialist_plan` to present bounded steps and unique task IDs. Read the deployed workers and allowed tools in `creative_os_create_specialist_run`'s current description. Give each job a question, scope, complete relevant context and justified cloud/provider budgets in US cents. Reuse plan IDs at dispatch. Read upstream results before starting dependent jobs. Do not point workers at local skill files they cannot access.

Use `creative_os_get_specialist_run` to read the existing task's status and stored answer. Cursor does not automatically render Creative OS web chat job cards or subscribe to their progress. Use bounded checks and preserve the task ID for continuation; do not create a replacement job while one is running. `creative_os_get_specialist_artifact` retrieves saved work after partial or interrupted runs. Report unavailable workers honestly and use inline research only within the user's requested execution scope.

## Review and hand off

Check citations, interpretation, coverage and limitations against the original question. Keep evidence, inference and hypotheses distinct. Inspect real media before making creative claims. Preserve disagreements and successful partial work.

For an evidence handoff, preserve sources, dated findings, evidence-versus-inference labels, reviewed media, coverage, limitations and a recommended next decision. Cloud workers return their server-defined answer schema; adapt those actual answers into the requested handoff. Do not require workers to create a second file-based protocol.

Finish at the agreed research deliverable. Story, deck, generation and campaign changes require relevant user scope. A completed job is not curated knowledge: merge durable facts into the marketing brain only when authorized.
